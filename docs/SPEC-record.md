# Запись сессии, хранение и выгрузка

## Версия формата
`cb-record-2` — с кодом причины (задача З-1, решение Р-8). Предыдущая — `cb-record-1`.
Старые записи при чтении получают `reasonCode` по строке; неизвестная строка — `R00` и `reasonUnknown: true`.
Менять только с записью в `DECISIONS.md`.

## Состав записи
| Группа | Поля | Происхождение |
|---|---|---|
| служебное | id, fmt, startedAt, tz, durationSec | — |
| ключ | reason, reasonCode, reasonGroup — в корне записи | выбрано человеком |
| stated | pre{ctx, area, areaOther, quality, level}, post{level, change, done, hinder}, note, postSkipped | заявлено человеком |
| set | organ, params{t-in, t-h1, t-out, t-h2, s-h2, c-freq, c-force, heart-rate}, preset, reactMethod (`voice` / `slider`, фактический способ; с З-12, Р-13) | задано настройкой |
| measured | device, samples; ряды `rr` и `spo2` — только в `series` (З-2, З-3) | измерено прибором |
| marked | пусто; события этапов и ряд реакции — в `series.events` и `series.react` (З-2, Р-12) | отмечено во время сессии |
| derived | holds, holdSec[] (с), holdOpen[], lastHoldOpen, contactSec[] (с, `null` без контакта), boundaryReached, response (±1 / `null`) — из `series.events` при сохранении (З-11); позже ВСР (З-3), acc* (З-8) | вычислено моделью |

`holdOpen` — задержка закончилась без `release` (следующим `hold` или концом сессии); её `holdSec` — нижняя граница. Записи без `derived` получают его при чтении из `series`, пока сырьё есть; сама запись не переписывается.

Причина — ключ записи, а не ответ: она задаёт шаблон и набор вопросов, по ней строятся указатель и сводка. Поэтому лежит в корне, рядом со служебными полями. `areaOther` — свободный текст, если область выбрана как «другое».

Состояния ответа: **дан**, **пропущен** (`__skipped`), **не задавался** (поля нет).

## Хранилище (IndexedDB `cb_records`)
- `index` — строка на сессию для списков и сводок (~200 байт), с `reasonCode`; поля: id, at, reason, reasonCode, area, areaOther, pre, post, dur, device.
  `pre`, `post` — ответ на главный вопрос (`level`, 0–10) или `null`, если ответа нет: пропущен или не задавался. Различие «пропущен / не задавался» хранится только в `sessions.stated`. В строках, записанных до 2026-10-02, в `post` может стоять `'__skipped'` — читается как пропуск, строка не переписывается.
  Производные для сводки (Р-14): `change` — ответ «что изменилось» или `null`; `holdN`, `holdSum` — число и сумма (с) полных задержек; `holdOpenN` — оборванные задержки; `contact` — был ли контакт.
  Источник истины — `sessions` и `series`; `index` их дублирует ради скорости, при расхождении верна `sessions`. В строках до Р-14 полей нет — сводка дочитывает их из `sessions`, строка не переписывается.
- `sessions` — полная запись без сырья (<1 КБ).
- `series` — сырые ряды (~10 КБ на 15 минут), запись на сессию, ключ равен id сессии (З-2):
  - `fmt` — версия формата;
  - `events` — `[{t, e, v?}]`, `t` в секундах от старта (0,1 с). `e`: `start`, `hold` (начало задержки), `contact` (А → Б1), `b2` (Б1 → Б2), `release`, `response` (`v` = ±1), `end`;
  - `react` — ряд реакции процесса «▶ Запустить процесс», если он шёл во время сессии: одно значение в секунду (последнее в секунде), `null` в секундах без точек; иначе `[]`;
  - `rr`, `spo2` — только при подключённом датчике (З-3), без датчика полей нет.

  Сырьё не перезаписывается и не пересчитывается. `sessions`, `index` и `series` пишутся одной транзакцией.

## Сводка (З-4, выполнено 2026-10-02)
📊 Аналитика, вкладка «Сводка» (первая); нынешняя аналитика — вкладка «Подробно».
Период по умолчанию 90 дней, переключение на 30 и на всё время.
Строка на пару «причина + область»: число сессий, среднее до, среднее после,
разница после − до (помогает ли в моменте), тенденция значения до (меняется ли фон) — наклон прямой, баллов за 30 дней.
Порог: при менее чем 5 сессиях средние не показывать.
Наверх выносятся три сигнала: рост значения до (у `well` — снижение), появление отметок «усилилась», обрыв практики. Пороги — в Р-14, предварительные.
Одна строка по периоду: средняя длительность полной задержки (оборванные — отдельным счётчиком) и доля сессий с контактом среди сессий с задержками.
Ниже: регулярность (доля дней с сессиями, самый длинный перерыв до сегодня), доля пропусков главного вопроса до и после, последние 5 заметок дословно.
Источник — `index` (Р-10, Р-14); заметки — из `sessions`, `series` не читается. При пустом журнале — пример на вымышленных данных, в базу не пишется.

## Выгрузка (не реализована — задача З-5)
- **Врачу-человеку** — одна-две страницы: шапка с оговоркой о происхождении данных, сигналы, строки по областям, регулярность, последние заметки дословно.
- **ИИ-ассистенту врача** — структурированный файл с метками происхождения и словарём полей в самом файле.
- **ИИ пациента** — то же плюс история запросов.
Выгружается сводка. Журнал и сырьё — отдельным действием и отдельным согласием.
Перед каждой выгрузкой человек видит свёрнутый список: период, состав, получатель.
